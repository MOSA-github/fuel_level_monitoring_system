ここで入力するURLは即時テスト表示専用で、本番の自動更新には保存されません。本番は下の「カメラID」とGitHub Actions Secret CAMERA_SOURCES_JSON の対応を使います。ブラウザ内の「針の解析テスト」で画素を読むにはカメラ側のCORS許可が必要です。設置角度・画角が変わったときは再校正が必要です。

必須：①〜③を順番に指定

①と③までの距離から検出半径を自動決定します。現在の針先端を設定する必要はありません。

04 / 保存と本番反映

設定後に何をすればよいか

  1. まず「針の解析テスト」で、今の画像から針が正しく認識されるか確認します。これは保存もGitHub通信もしません。
  2. 下書きを保存は、このブラウザだけに保存します。本番にはまだ反映されません。
  3. 本番へ反映する方法は2通りのどちらか一方です。
    A：下の「GitHubへ設定を反映」を押す → このボタン自身が config/gauges.json を更新し、mainへcommitまで行います。別途commit操作は不要です。
    B：「設定JSONを書き出す」を使う → 手元のリポジトリで config/gauges.json を置き換え、自分でcommit・pushします。
  4. mainへのcommit/push後はActionsが起動します。設定変更時は次の解析対象になるため、通常はそのまま結果更新まで待てばOKです。
  5. 以後は5分ごとのActions起動時に、各計器の「実行間隔」を確認して自動解析します。設定を変えずに今すぐ再測定したい場合だけ「GitHub保存済み設定を今すぐ解析」を使います。
GitHubへ本番反映

ページから直接反映する管理者向けです。Fine-grained PAT に、このリポジトリの Contents: Read and write、Actions: Read and write を設定してください。トークンはメモリ内のみで使用します。
